# Zomato Restaurant Rating Predictor

Predicts a restaurant's **Aggregate rating (0–5)** from its attributes (city, cuisine,
cost, price range, table booking / online delivery, votes) using a regression model
trained on the Zomato restaurants dataset, deployed as a FastAPI service.

## Dataset

- **Source:** [Zomato Restaurants Data](https://www.kaggle.com/datasets/shrutimehta/zomato-restaurants-data) (Kaggle)
- **Size:** 9,551 restaurants, 21 raw columns, spanning 15 countries and 140+ cities
- **File:** `dataset/zomato.csv`
- **Target:** `Aggregate rating` (only restaurants with at least one rating are used for training — unrated restaurants are excluded via an `Is Rated` filter)

### Preprocessing (see `notebooks/zomato_pipeline.ipynb` and `src/train_model.py`)

- Dropped `Longitude` / `Latitude` (not used as features)
- Converted `Average Cost for two` to USD using a currency lookup table, since costs were recorded in 12 different local currencies
- Cleaned/normalized string and Yes/No columns; dropped `Switch to order menu` (constant column)
- Imputed missing `Cuisines` as `"Unknown"`
- Removed duplicate restaurants (by `Restaurant ID`, then full-row duplicates)
- Capped outliers in `Votes` and `Average Cost for two (USD)` using the IQR rule
- Label-encoded `City`, `Primary Cuisine`, `Has Table booking`, `Has Online delivery`
- Engineered features: `Primary Cuisine` (first listed cuisine), `Num Cuisines`, `Votes (log)` (log1p of votes), `City Restaurant Count` (restaurants per city, as a proxy for market density)
- Standard-scaled all 11 model features

## Algorithms compared

Four regression algorithms were trained on the **identical train/test split** (`test_size=0.2, random_state=42`) so the comparison is fair:

| Algorithm | MAE | RMSE | R² |
|---|---|---|---|
| **XGBoost** | **0.2448** | **0.3257** | **0.6571** |
| Random Forest | 0.2626 | 0.3494 | 0.6052 |
| Decision Tree | 0.2746 | 0.3663 | 0.5661 |
| Linear Regression | 0.2854 | 0.3790 | 0.5357 |

**Selection rule:** lowest RMSE on the held-out test set. RMSE was chosen over plain MAE
because it penalizes larger errors more heavily, which matters on a 0–5 rating scale
where a 2-star miss is far more damaging than a 0.2-star miss.

**Winner: XGBoost.** It is refit on the full rated dataset (7,403 rows) and is the
only model saved to `models/` and served by the API. The other three are trained and
scored purely for the comparison table above — they are not deployed.

Run `python src/train_model.py` to reproduce this table and print 3 sanity-check
predictions (sample input → predicted vs. actual rating) for the winning model.

## Setup

```bash
pip install -r requirements.txt

# train (or retrain) the model — writes models/*.joblib + models/metrics.json
python src/train_model.py

# run the API from the project root
python -m uvicorn api.app:app --reload --port 8000
```

The API auto-trains on first startup if `models/model.joblib` doesn't exist yet, so
`python src/train_model.py` is optional but recommended (it prints the comparison
table and sanity checks).

Open `api/index.html` in a browser (or serve it) to use the included frontend — it
auto-discovers the running API via `/openapi.json`.

## Backend

The machine learning model is deployed through a **FastAPI backend**.

FastAPI is responsible for:

- Loading the trained XGBoost model
- Loading the scaler and categorical encoders
- Validating user input
- Preprocessing prediction data
- Generating restaurant rating predictions
- Returning prediction results as JSON

### Backend Structure

```text
api/
├── app.py        # FastAPI backend
└── index.html    # Optional frontend
```

The main backend file is:

```text
api/app.py
```

It provides the following API endpoints:

| Method | Endpoint   | Purpose                                       |
| ------ | ---------- | --------------------------------------------- |
| `GET`  | `/health`  | Check whether the API is running              |
| `GET`  | `/options` | Get valid cities, cuisines, and other options |
| `POST` | `/predict` | Predict the restaurant's aggregate rating     |

### Running the FastAPI Backend

Install the dependencies:

```bash
pip install -r requirements.txt
```

Train the model:

```bash
python src/train_model.py
```

Start the FastAPI backend:

```bash
python -m uvicorn api.app:app --reload --port 8000
```

The backend will run at:

```text
http://127.0.0.1:8000
```

### FastAPI Documentation

Interactive API documentation is automatically available at:

```text
http://127.0.0.1:8000/docs
```

You can use the Swagger UI to test `/health`, `/options`, and `/predict` directly from the browser.

### Backend Prediction Flow

```text
User Input
    ↓
FastAPI
    ↓
Input Validation
    ↓
Preprocessing
    ↓
Scaler + Encoders
    ↓
XGBoost Model
    ↓
Predicted Rating
    ↓
JSON Response
```

The FastAPI backend serves the trained **XGBoost model** and provides the prediction functionality through a REST API.

## API usage

**`GET /health`** — service status.

**`GET /options`** — valid cities / cuisines / country codes the model was trained on.

**`POST /predict`** — returns the predicted rating.

```bash
curl -X POST http://127.0.0.1:8000/predict \
  -H "Content-Type: application/json" \
  -d '{
    "Country Code": 1,
    "City": "New Delhi",
    "Primary Cuisine": "North Indian",
    "Num Cuisines": 3,
    "Average Cost for two (USD)": 20,
    "Has Table booking": "Yes",
    "Has Online delivery": "No",
    "Price range": 3,
    "Votes": 500,
    "Votes (log)": 6.2,
    "City Restaurant Count": 5473
  }'
```

Response:

```json
{
  "predicted_rating": 3.86,
  "aggregate_rating": 3.86,
  "rating_text": "Good",
  "interpretation": "Good"
}
```

An unrecognized `City` or `Primary Cuisine` returns a `422` pointing to `GET /options`.

## Deploying (Render + Vercel)

The backend (FastAPI) and frontend (`api/index.html`) deploy separately — Render
runs the Python API, Vercel hosts the static frontend, and the two are connected
with one URL.

## Results summary

XGBoost outperformed Linear Regression, Decision Tree, and Random Forest on every
metric, cutting RMSE by roughly 14% versus the next-best model (Random Forest) and
explaining about 66% of the variance in restaurant ratings (R² = 0.657). The
strongest predictors were `Votes` / `Votes (log)` and `City Restaurant Count` —
restaurants with more community engagement and restaurants in cities with denser
listings tend to have more stable, predictable ratings, while low-vote restaurants
are noisier and harder to predict.
